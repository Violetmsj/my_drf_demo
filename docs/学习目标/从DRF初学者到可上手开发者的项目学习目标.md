# 从 DRF 初学者到可上手开发者的项目学习目标

这份文档不是单纯在列功能清单，而是在帮你定义一个“成长型项目”。

目标不是把接口写出来就结束，而是通过完成这个项目，让你真正建立起后端开发者的基本工作方式:

- 能看懂需求，并把需求拆成数据、接口、权限、校验、异常处理几个部分
- 能独立完成一个小型后台系统的核心开发
- 能理解“为什么要这样设计”，而不是只会跟着教程敲代码
- 能在以后接触真实项目时，不再只会想页面，而是也会开始想模型、规则、边界和数据流

---

## 一、项目总目标

你要开发的，不只是一个“能跑”的 DRF Demo，而是一个具备真实项目雏形的小型后台系统。

这个系统至少要覆盖以下基础能力:

1. 用户登录
2. 添加用户
3. 基础数据的增删改查

但如果你的目标是从“DRF 初学者”成长到“可以直接上手做项目的开发者”，只做到上面 3 件事还不够。

你还必须逐步掌握这些能力:

1. 用户认证和登录态管理
2. 用户与角色/权限的关系
3. 数据模型设计
4. 序列化与数据校验
5. 列表、详情、创建、更新、删除的完整 API 设计
6. 分页、搜索、筛选、排序
7. 业务规则约束
8. 错误处理与统一返回
9. 接口测试与基本调试能力
10. 项目结构组织能力

所以，这个学习项目建议你把它理解成:

**一个面向后台管理场景的“小型课程管理系统 / 基础数据管理系统”。**

这个系统既能贴合你现在项目已有的课程场景，也能帮助你学习真实业务开发中最常见的后端工作。

---

## 二、项目定位

### 1. 目标身份

你现在的身份是:

- 会前端开发
- 对交互和页面比较熟
- 对后端的数据流、权限、模型设计、接口设计还不够熟

完成这份文档中的目标后，你希望达到的状态是:

- 能独立设计一个小型 Django + DRF 项目的后端部分
- 能根据需求自己拆模型、写序列化器、写视图、配权限
- 能和前端约定接口，而不是只会“后端返回什么我就先用什么”
- 能理解后端开发中的“规则意识”和“边界意识”

### 2. 目标系统

推荐你把本次学习项目定义为:

**课程管理后台系统（带用户与权限能力）**

建议包含以下核心对象:

1. 用户 `User`
2. 课程 `Course`
3. 课程分类 `CourseCategory`
4. 可选扩展对象:
   - 标签 `Tag`
   - 选课记录 `Enrollment`
   - 操作日志 `OperationLog`

其中，最小闭环至少要有:

1. 用户体系
2. 一个业务主对象的 CRUD
3. 与该业务主对象相关的分类或归属关系

## 三、功能目标总览

下面我把功能分成三个层级:

- `P0`：必须完成，不完成就还停留在“会写几个接口”的阶段
- `P1`：建议完成，完成后更接近真实项目开发
- `P2`：进阶项，完成后你会明显更像一名能独立推进后端任务的开发者

## 四、功能清单、实现程度与验收标准

## 4.1 用户认证模块

### 功能点 1：用户登录

- 实现程度：`P0 必须完成`
- 目标说明：
  - 用户输入账号和密码后可以登录系统
  - 登录成功后，后续请求可以识别当前用户
- 你必须学会的东西：
  - `authenticate()` 的作用
  - `TokenAuthentication` 或 `SessionAuthentication` 的工作方式
  - `request.user` 是怎么来的
- 验收标准：
  - 存在登录接口，例如 `POST /api/auth/login/`
  - 用户输入正确账号密码时返回登录成功结果
  - 返回值中至少包含用户信息和登录凭证
  - 用户输入错误账号或密码时，能返回明确错误信息
  - 登录后访问需要认证的接口时，可以正确识别当前用户
  - 未登录访问受保护接口时，返回 401 或明确的未认证提示

### 功能点 2：获取当前登录用户信息

- 实现程度：`P0 必须完成`
- 目标说明：
  - 前端刷新页面后，仍然能通过接口知道“我是谁”
- 你必须学会的东西：
  - 当前用户接口为什么重要
  - 如何基于登录态恢复前端页面状态
- 验收标准：
  - 存在接口，例如 `GET /api/auth/me/`
  - 已登录用户调用时，能返回当前用户的基本信息
  - 未登录调用时，返回未认证结果

### 功能点 3：退出登录

- 实现程度：`P0 必须完成`
- 目标说明：
  - 用户可以退出当前登录状态
- 你必须学会的东西：
  - Token 模式下退出登录的处理思路
  - 前后端各自该负责什么
- 验收标准：
  - 存在退出接口，例如 `POST /api/auth/logout/`
  - 退出后再访问受保护接口时，不能再以原登录身份通过
  - 前端本地保存的登录凭证能够被清理

### 功能点 4：用户注册或管理员创建用户

- 实现程度：`P0 必须完成`
- 目标说明：
  - 系统要支持新增用户
  - 你提出的“添加用户”需求，就落在这里
- 你必须学会的东西：
  - 密码不能明文存储
  - 用户名唯一校验
  - 序列化器中的字段校验与 `create()` 流程
- 验收标准：
  - 存在新增用户能力，可以是自助注册，也可以是管理员创建用户
  - 同名用户不能重复创建
  - 密码字段不会以明文形式出现在接口返回里
  - 创建成功后可以用新账号登录
  - 用户创建失败时，能指出具体失败原因

---

## 4.2 用户管理模块

### 功能点 5：用户列表与用户详情

- 实现程度：`P1 建议完成`
- 目标说明：
  - 后台系统通常需要查看用户列表和某个用户详情
- 你必须学会的东西：
  - 列表接口和详情接口的区别
  - 如何控制哪些字段能给别人看，哪些字段不能随便暴露
- 验收标准：
  - 存在用户列表接口和用户详情接口
  - 普通用户不能随便查看敏感字段
  - 列表接口支持基础分页
  - 能通过用户 ID 获取指定用户详情

### 功能点 6：用户状态管理

- 实现程度：`P1 建议完成`
- 目标说明：
  - 用户不仅仅是“有或没有”，通常还会有启用、禁用等状态
- 你必须学会的东西：
  - `is_active` 之类状态字段的业务意义
  - “删除用户”和“禁用用户”是两种不同思路
- 验收标准：
  - 管理员可以禁用某个用户
  - 被禁用用户不能正常登录
  - 接口层面对状态变化有明确限制和提示

---

## 4.3 基础数据 CRUD 模块

### 功能点 7：课程 CRUD

- 实现程度：`P0 必须完成`
- 目标说明：
  - 这是你的核心业务对象，必须完整做通
- 你必须学会的东西：
  - 模型设计
  - 序列化器字段映射
  - `ModelViewSet` 的基本使用
  - 创建人、更新时间等字段的处理
- 验收标准：
  - 存在课程列表、课程详情、创建、更新、删除接口
  - 可以新增课程
  - 可以查看课程详情
  - 可以修改课程信息
  - 可以删除课程
  - 接口返回结构稳定，字段语义清晰
  - 创建和更新时有必要的数据校验

### 功能点 8：课程分类 CRUD

- 实现程度：`P0 必须完成`
- 目标说明：
  - 真实项目里的主业务对象通常不会是孤立的，至少会有分类、归属、标签等辅助对象
- 你必须学会的东西：
  - 一对多关系
  - 外键字段在 serializer 中如何展示
  - 创建课程时如何关联分类
- 验收标准：
  - 存在课程分类的完整 CRUD 接口
  - 一个课程可以归属于某个分类
  - 删除分类时，系统行为明确
  - 行为可以是禁止删除、级联删除或解除关联，但必须是你明确设计过的

### 功能点 9：搜索、筛选、排序

- 实现程度：`P1 建议完成`
- 目标说明：
  - 只有 CRUD 还不够，后台系统最常见的实际需求之一就是“把数据找出来”
- 你必须学会的东西：
  - `filter_backends`
  - 精确筛选和模糊搜索的区别
  - 排序字段的控制
- 验收标准：
  - 列表接口至少支持 1 个关键字搜索字段
  - 至少支持 1 个业务字段筛选，例如分类、状态、创建人
  - 至少支持创建时间或更新时间排序
  - 搜索、筛选、排序可以组合使用

### 功能点 10：分页

- 实现程度：`P0 必须完成`
- 目标说明：
  - 分页是列表接口的基本能力，不应该等数据多了才补
- 你必须学会的东西：
  - 为什么列表接口不能默认一次返回全部数据
  - DRF 分页结构怎么设计和读取
- 验收标准：
  - 列表接口返回分页结构
  - 至少包含总数、下一页、上一页、结果列表等信息
  - 前端可以基于分页参数切换页面

---

## 4.4 权限与业务规则模块

### 功能点 11：只有创建者可编辑

- 实现程度：`P0 必须完成`
- 目标说明：
  - 这是你当前项目里非常关键的后端思维训练点
  - 后端不是只处理数据，还要守住规则
- 你必须学会的东西：
  - 对象级权限
  - “能看”和“能改”往往不是同一回事
- 验收标准：
  - 课程创建者可以修改和删除自己创建的课程
  - 非创建者不能修改或删除该课程
  - 系统返回明确的无权限提示

### 功能点 12：管理员与普通用户权限区分

- 实现程度：`P1 建议完成`
- 目标说明：
  - 真实系统里，权限通常不是“登录即可”
- 你必须学会的东西：
  - `IsAuthenticated`
  - 自定义权限类
  - 管理员接口与普通接口的边界
- 验收标准：
  - 至少有一类接口只能管理员访问
  - 普通用户访问管理员接口时被拒绝
  - 管理员能执行用户管理相关操作

### 功能点 13：数据校验规则

- 实现程度：`P0 必须完成`
- 目标说明：
  - 后端必须对脏数据负责，不能只相信前端
- 你必须学会的东西：
  - 字段级校验
  - 对象级校验
  - 业务规则写在什么层更合适
- 验收标准：
  - 至少为关键业务字段配置必填校验
  - 至少有 1 个跨字段校验规则
  - 非法数据进入时，接口会拒绝并说明原因

---

## 4.5 接口质量模块

### 功能点 14：统一错误响应意识

- 实现程度：`P1 建议完成`
- 目标说明：
  - 一个能直接上手项目的开发者，不只是能把接口打通，还要让接口“可协作”
- 你必须学会的东西：
  - 常见状态码的基本语义
  - 校验错误、权限错误、资源不存在的区别
- 验收标准：
  - 400、401、403、404 等常见错误场景能区分
  - 返回结果能帮助前端快速定位问题
  - 不把后端异常堆栈直接暴露给前端

### 功能点 15：接口文档或接口说明

- 实现程度：`P1 建议完成`
- 目标说明：
  - 能写接口，不代表别人能接得上
  - 你要开始培养“交付给别人使用”的意识
- 你必须学会的东西：
  - 接口路径、请求参数、返回结构、错误场景的表达方式
- 验收标准：
  - 至少为核心接口编写简单说明文档
  - 每个核心接口能说明用途、请求方式、入参、返回值、异常场景

---

## 4.6 测试与调试模块

### 功能点 16：核心接口测试

- 实现程度：`P1 建议完成`
- 目标说明：
  - 你要从“接口能用”过渡到“接口可靠”
- 你必须学会的东西：
  - DRF 测试客户端的基础使用
  - 正常路径与异常路径都要测
- 验收标准：
  - 至少为登录、用户创建、课程 CRUD、权限限制编写测试
  - 至少覆盖成功与失败两类场景
  - 修改代码后可以通过测试验证主要功能没有回归

### 功能点 17：接口调试能力

- 实现程度：`P0 必须完成`
- 目标说明：
  - 你以后真正做项目时，调试能力非常关键
- 你必须学会的东西：
  - 看日志
  - 看接口请求和响应
  - 定位问题是在前端、代理、后端路由、认证还是数据库
- 验收标准：
  - 你能独立定位至少以下问题：
    - 404 是路由问题还是代理问题
    - 401 是未登录还是 Token 错误
    - 400 是字段校验失败还是参数缺失
    - 403 是认证失败还是权限不足

## 4.7 项目工程化基础

### 功能点 18：合理的项目结构

- 实现程度：`P0 必须完成`
- 目标说明：
  - 会写代码和会组织项目，是两回事
- 你必须学会的东西：
  - `models.py`、`serializers.py`、`views.py`、`permissions.py`、`urls.py` 分工
  - 为什么接口逻辑不应该全部堆在一个文件里
- 验收标准：
  - 代码按职责进行拆分
  - 路由、权限、序列化器、模型职责清晰
  - 新增一个功能时，你知道应该改哪些地方

### 功能点 19：基础代码规范

- 实现程度：`P1 建议完成`
- 目标说明：
  - 真实项目开发不是“能跑就行”，还要可读、可维护
- 你必须学会的东西：
  - 基本命名规范
  - 重复逻辑抽离意识
  - 使用格式化和静态检查工具
- 验收标准：
  - 关键命名有明确语义
  - 明显重复代码有被整理
  - 能通过 `ruff check` 与必要格式化

## 五、推荐的阶段性开发目标

如果一下子把所有功能都堆上去，你很容易再次陷入“知道要做很多，但不知道先做什么”的状态。

所以更推荐你按下面 4 个阶段推进。

### 阶段一：打通最小闭环

目标：

1. 用户注册或创建用户
2. 用户登录
3. 获取当前用户
4. 退出登录
5. 课程 CRUD

完成标准：

- 你已经可以从前端完成登录和课程数据管理
- 系统具备最基本的认证能力和业务 CRUD 能力

这一步完成后，你会从“会跑 DRF 教程”进步到“能做一个最小后端系统”。

### 阶段二：补上真实项目最基础的规则

目标：

1. 创建者权限控制
2. 数据校验
3. 分页
4. 分类 CRUD

完成标准：

- 你开始不只是“把数据存进去”，而是能控制“谁能改、什么数据能进”

这一步完成后，你会从“会写接口”进步到“开始有后端规则意识”。

### 阶段三：补上后台系统常用能力

目标：

1. 用户列表与详情
2. 用户状态管理
3. 搜索、筛选、排序
4. 管理员权限控制

完成标准：

- 你的系统开始更像真实后台，而不是单纯的示例接口集合

这一步完成后，你会从“会做 demo”进步到“能做基础后台模块”。

### 阶段四：补上交付能力

目标：

1. 核心接口测试
2. 简单接口文档
3. 错误响应规范
4. 代码结构整理

完成标准：

- 你不仅能开发，还能让别人接入、维护和继续扩展

这一步完成后，你会更接近“可以直接上手项目开发”的状态。

## 六、最终验收标准

当你完成这个学习项目时，建议你用下面这份“毕业标准”来衡量自己，而不是只看“功能有没有写完”。

### 1. 功能层面

- 可以完成登录、退出、当前用户获取
- 可以完成新增用户
- 可以完成至少一个主业务对象和一个辅助对象的 CRUD
- 可以完成分页、基础搜索或筛选
- 可以完成对象级权限控制

### 2. 理解层面

- 你知道认证和权限不是一回事
- 你知道 serializer 不只是“返回 JSON”，还承担校验职责
- 你知道 viewset 不只是“偷懒少写代码”，而是在组织一组资源接口
- 你知道模型设计会直接影响接口设计和前端使用体验
- 你知道后端开发的重点不是页面，而是规则、数据和边界

### 3. 工程层面

- 你能独立新增一个模型并配套完成 serializer、view、url
- 你能独立为某个接口加上权限控制
- 你能独立定位常见 400/401/403/404 问题
- 你能读懂并修改当前项目中的 DRF 代码结构

如果上面这些你都做到了，那么你基本就已经不再只是“DRF 初学者”，而是一个:

**可以开始直接参与小型 Django/DRF 项目开发的开发者。**

## 七、给你的一个建议

这份学习目标文档最重要的价值，不是它列了多少功能，而是它帮你建立了一个顺序:

1. 先打通
2. 再补规则
3. 再补后台常用能力
4. 最后补可维护性和交付能力

你以前作为前端开发者，天然更容易先看到“页面和交互”。

而这次学习 DRF，你要刻意训练自己每次都多问几句:

1. 这个功能要存什么数据？
2. 这些数据之间是什么关系？
3. 谁可以看？谁可以改？
4. 非法数据怎么拦住？
5. 接口返回后，前端要怎么用？

当你开始习惯这样想问题时，你就真的在从“前端视角学后端”慢慢转变成“具备后端开发思维”了。

## 八、建议你下一步立刻做的事

如果你想把这份文档真正变成行动，可以马上开始做这 4 件事:

1. 先确定你的主业务对象是不是继续用 `Course`
2. 给 `Course` 增加一个分类模型 `CourseCategory`
3. 把“注册 / 登录 / 当前用户 / 退出登录”这条链路完整跑通
4. 给课程接口补上“只有创建者可以修改”的权限控制

这 4 步做完，你的学习会立刻从“看懂一点点 DRF”进入“真的在做一个后端系统”。
